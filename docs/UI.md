# Frostcap UI

React 19 + Vite 8 + TypeScript 7 (native `tsc`; it has no JS API), zustand for state, `motion` (LazyMotion with `domAnimation`), lucide-react icons, vitest for tests. No UI kit, no web fonts, no network requests. Lives in `ui/`.

```
npm --prefix ui install --cache .toolchain\npm-cache
npm --prefix ui run dev        # http://localhost:5173 (matches tauri.conf.json devUrl)
npm --prefix ui test           # vitest
npm --prefix ui run typecheck
npm --prefix ui run build      # tsc --noEmit && vite build -> ui/dist
```

## Contract

Rust is the source of truth: `docs/CONTRACT.md` and the golden JSON in `fixtures/` (generated by `golden_fixtures` in `src-tauri/src/dto.rs`). The wire shapes are transcribed literally in `ui/src/contract.ts`, and **every** conversion to the editor model lives in `ui/src/backend.ts`.

Tests that pin the contract:

- `ui/src/contract.commands.test.ts`: for each fixture command, the adapter sends exactly the fixture's `args` and maps its `response` and `error`. Events are checked against their fixture shapes.
- `ui/src/contract.test.ts`: `project.sample.json` and `load_project` / `save_project` round-trip exactly. Also covers pixel/time/trim/style mapping and media path confinement.
- `ui/src/mock.contract.test.ts`: the browser mock (`mockBackend.ts`) answers with the same shapes as the fixtures, so the demo exercises the real adapter.

| Rust (wire) | UI model | Rule |
|---|---|---|
| `tracks.*[].tMs`, `edits.zoomSegments[].startMs/endMs` | `t`, `start/end` | same milliseconds on the video clock |
| pixel `x/y`, focus `rect` | 0..1 | ÷ `canvas.width/height`; out-of-canvas values stay out of range |
| `edits.trims` (cut ranges) | `clips` (kept ranges) | complement over `[0, durationMs]`; overlapping or unsorted trims are merged, clamped, and empty ones dropped |
| (none) | adjacent clips (splits) | `edits.ui.splits` |
| `zoomSegments[].center`, `origin` | `cx, cy`, `auto` | `origin` defaults to `auto` like serde |
| easings | same names | `ease()` and `zoomAt()` match `frostcap-render/src/math.rs` (tested) |
| `style.background` CSS string | `{id, angle, stops}` | parsed, then re-formatted without spaces |
| `padding` 0..0.4, `shadow` 0..1 | % 0..40, 0..100 | ×100, rounded to 1e-9 so round-trips are exact |
| `cursorBaked` | `cursorBaked`, `style.cursor.visible = false` | never draws a second cursor |
| `media.*` file names | `url` via `convertFileSrc` | `joinPath` accepts only bare file names (no drive, root, scheme, separators or `..`); otherwise `url = null` |
| editor-only state | `edits.ui` | opaque to Rust and round-tripped verbatim |
| any saved number | same | clamped to `LIMITS` (zoom center 0..1, scale, `endMs >= startMs`, `cornerRadius` 0..4096, ...); non-finite values become the editor default (NaN would be `null` and fail the save); ms values (zooms, trims, splits) are whole; a background over 4096 bytes falls back to the default. `limits.drift.test.ts` parses `docs/CONTRACT.md` and the `check_f64` calls in `Project::validate` so `LIMITS` cannot drift |
| `{code, message}` errors | `BackendError{code}` | `describeIssue()` gives actionable text for `disk_full`, `source_gone`, `no_h264`, `invalid_path`, `invalid_project`, `permission`, `io`, `internal` |

Saving reuses `project.wire.tracks` **by reference**, so tracks are never copied. Undo snapshots share arrays; a test with 400k samples covers this.

### Commands and events used

- **Commands:** `list_sources` (thumbnails), `list_cameras`, `pick_region`, `start_recording` (`keys`, `webcam`), `pause_recording`/`resume_recording`, `stop_recording`, `recording_state`, `load_project`/`save_project`, `list_recent_projects`, `recover_project`, `scrub_project`, `generate_auto_zoom`, `export_project` (`preset` object + `jobId`), `cancel_export`, `pick_project`/`pick_folder`/`pick_save_path`, `reveal_in_folder`, `default_output_dir`, `hotkeys`.
- **Events:** `recording://tick` (with `paused`), `recording://warning`, `recording://error`, `recording://stopped` (auto-stop: opens what was saved and explains the error), `export://progress` (by `jobId`, with `stage`), `hotkey://pressed`.
- **Export target:** must come from `pick_save_path`, because the backend rejects other targets. The sheet opens the dialog on Export if no path was chosen yet.

### Privacy and security (UI side)

- **Key capture:** off by default. The recorder switch only enables **Shortcuts only**. **All keys** requires Settings plus a confirmation that mentions passwords, and the recorder badge then reads "All keys recorded" in red.
- **Window titles:** opt-in (Settings → Privacy, default off). `start_recording` gets `windowTitles: true` only when the user opted in; otherwise the backend stores only an anonymous `windowId`.
- **Hotkeys:** `hotkey://pressed` with `handled:false` while idle only starts recording if the main window is visible and not minimized, and always through the visible countdown. Hints show only chords that `hotkeys` reports as registered.
- **Global hotkeys:** Settings → Global recording hotkeys shows each chord, marks chords another app owns as not active, and records new ones. They are validated like `Chord::from_str` (`lib/hotkeys.ts`: Ctrl or Win, at least two modifiers, never Ctrl+Alt alone because that is AltGr) and saved with `set_hotkeys`, which persists them; backend errors are shown inline.
- **Capture border:** always on, set by the backend. There is no UI setting.
- **`freezePrototype`:** `ui/src/dev/freeze-check.html` (dev only) freezes `Object.prototype` before loading the app, like Tauri does. The browser check found no errors.

## Preview

`ui/src/lib/media.ts` (`MediaEngine`):

- **Video:** `screen.mp4` (and `webcam.mp4`) play in hidden `<video>` elements. While playing, the video is the clock. `requestVideoFrameCallback` triggers redraws, and trimmed gaps are skipped by seeking.
- **Audio:** the mic and system WAVs play as `<audio>` elements through Web Audio gain nodes (the gains are in the Audio tab). Each track sits at its `offsetMs` (negative allowed): it is delayed when it starts later than the video, and corrected when it drifts more than 60 ms.
- **Waveform:** `lib/peaks.worker.ts` streams the WAV and computes 10 ms peaks (`lib/wav.ts`: PCM 8/16/24/32, float 32/64, EXTENSIBLE, unknown data size; tested).
- **Browser demo:** no URLs, so the synthetic scene and demo peaks are used, and the preview is labelled "Demo scene".

## Recording UI

- **Warnings and errors:** `recording://warning` and `recording://error` become toasts with actionable text. Errors use `role=alert`.
- **Key capture:** off by default. While it is on, the recorder bar shows an amber **Keys on** badge. Settings → Privacy explains what is stored.
- **Recovery:** a banner lists interrupted recordings with Recover buttons.
- **Open project / Browse:** both are enabled. In the browser demo they pick sample paths.

## Theming, accessibility

- **Surfaces:** themes and surfaces are as in docs/BRAND.md. Sliding indicators (segmented controls, inspector tabs) are CSS transforms (`lib/indicator.ts`), which allowed switching motion from `domMax` to `domAnimation`.
- **Keyboard:** Ctrl+1/2/3 are ignored while typing (`lib/keys.ts`, tested). The export dialog focus trap is `lib/focus.ts` (tested). It wraps in both directions and recovers focus that escaped or sat on a disabled control.
- **Contrast audit:** `ui/src/dev/contrastAudit.ts` (dev only; see the report for results). For every visible text element it composites the ancestor glass tints over the app background and over each mesh blob colour, then reports the worst-case WCAG ratio.

## Keyboard map

Space or K play/pause · S split · Z add zoom · Del delete · Ctrl+Z / Ctrl+Y undo/redo · ←/→ frame (Shift: 1 s) · Home/End · Ctrl+S save · Ctrl+E export · Ctrl+1/2/3 views. On a focused zoom segment, ←/→ moves it and Alt+←/→ resizes it.

## Review fixes (UI/UX)

- **Unsaved edits:** opening another project (recent, Open, Recover, a new recording) or closing the window asks **Save / Discard / Cancel** (`store/guard.ts`). In Tauri this uses `onCloseRequested`; in the browser, `beforeunload`.
- **Failed loads:** these keep the previous project. The error view offers **Back** and **Retry**.
- **Dirty state:** compares against the last saved snapshot, so undoing back to it clears "Edited".
- **Timeline:** trim handles are siblings of the clip buttons, not nested inside them. Clicking a clip selects it and moves the playhead there, so S splits at the click; dragging scrubs after a 4 px threshold. The hint is short and not a live region.
- **Undo toasts:** after deleting a segment, clip or caption, after Apply to all, and after Auto zoom.
- **Toasts:** at most 3. Info lasts 5 s, warnings 10 s, errors stay until dismissed, and action toasts last at least 10 s. Hover or focus pauses them. F6 jumps to the newest toast's action.
- **Export sheet:** every setting is disabled while exporting. The progress area is always reserved, aspect cards use roving tabindex with arrow keys, and Cancel calls `cancel_export`.
- **Settings:** the output folder shows `default_output_dir` (old `%USERPROFILE%` values are migrated away) and is validated on blur.
- **Recovery banner:** lists every interrupted recording, with **Recover all**.
- **Countdown:** has a persistent live region and a focus trap.
- **Preview focus click:** inverts the current zoom transform (`canvasToContent`).
- **Accessibility and layout:** a skip link, `aria-controls` only for the rendered panel, a 12 px minimum font size, `--recbar-space` bottom padding, and `.page__inner` capped at 1480 px.

## Internationalization

`ui/src/i18n/`: a typed message catalog and `t()`, no library. `en.ts` is the source of truth for the key set (`MessageKey`); `es`, `de`, `fr`, `pt-BR` and `ja` are `Record<MessageKey, Msg>`, so `tsc` rejects missing or extra keys. A `Msg` is a string with `{name}` placeholders, or an object of `Intl.PluralRules` categories (`one`, `other`, ...; `other` required) selected by the `count` parameter. `tRich()` turns `<b>...</b>` into elements. Lookup falls back to English, then to the key.

- **Language:** `Settings.language` is `"system"` (default, from `navigator.languages`, `pt-*` maps to pt-BR) or one locale. It is persisted with the other settings (`frostcap.settings.v1`) and chosen in Settings → Appearance. A change remounts the app tree (`App.tsx` keys a fragment on the locale) so every string is re-translated; toasts already shown keep their old text.
- **Not translated by design:** Frostcap, key names (Ctrl, Shift, Space, Home...), MP4/GIF/H.264, units such as ms, px, dB, Hz. Messages that come from the Rust backend (`error.message`) stay English; only the surrounding advice (`describeIssue`) is translated.
- **Tests:** `i18n.test.ts` (same keys in every locale, same placeholders, no empty strings, plural `other` present, detection, plurals, interpolation) and `hardcoded.test.ts`, which parses every non-test `.tsx` (vite's `parseAst`) and fails on JSX text or on `aria-label`/`title`/`placeholder`/`alt`/`label`/`hint` literals containing letters. Allowlist: `Frostcap`, the version line, `Home`/`End`/`Space`. `src/test/setup.ts` pins `navigator.language` to `en-US` so tests do not depend on the developer's OS language.
- **Layout check:** `node ui/scripts/screenshots.mjs --lang de --theme dark --width 1280 --height 800 --out <dir>` (same for `ja`) renders every screen in that locale.

## In-app self-test (dev harness)

`ui/src/selftest/`. `runner.ts` (ordered steps, stop on first failure, cleanup steps always run, JSON report), `flow.ts` (the scripted flow over an injected `Deps`, unit-tested with fakes), `index.ts` (real wiring: Web Audio 440 Hz tone, `<video>`/`fetch`+`decodeAudioData` probes, the editor store). `main.tsx` imports it only when `import.meta.env.DEV` or the build was made with `VITE_FROSTCAP_SELFTEST=1`; a normal production build does not contain it (checked: the dist has no self-test strings). Even then it runs only if the backend answers `launch_options() -> { selftest: true }`; if the command is missing it does nothing.

Flow: `list_sources`, record the primary display ~3 s with system audio while the tone plays (pause 0.5 s, resume), `load_project`, screen.mp4 loads in a `<video>` through the asset protocol, reports a duration and seeks to the middle, system WAV decodes with peak >= 0.01, `generate_auto_zoom`, edit (zoom, caption, frame macos) and `save_project`, reload and compare, `export_project` to `<parent of the project>/frostcap-selftest-*.mp4` (inside `Videos\Frostcap`, not inside a project folder, which the path policy accepts without `pick_save_path`), the output loads in a `<video>` with the expected duration, then `selftest_cleanup`. The report is logged as `[selftest] {...}` and sent to `write_selftest_report({report})`.

## Screenshots

`node ui/scripts/screenshots.mjs` starts Vite if it is not running, drives headless Edge over CDP (Node's built-in `fetch`/`WebSocket`, profile in `.toolchain/edge-screenshot-profile`) with the mock backend and writes 1600x1000 PNGs of Recorder, Editor, Export sheet and Settings, dark and light, into `assets/screenshots/`. It uses `data-testid`s: `nav-<view>`, `recent-<i>`, `editor-export`, `export-sheet`.

## Editor v2 (annotations, speed, webcam effects, images, batch)

- **Wire/model:** `edits.annotations`, `edits.speed`, `style.backgroundImage`, the new `style.webcam` fields and the `laptop`/`phone` frames are typed in `contract.ts`/`types.ts`, read with Rust defaults and clamped to the schema in `backend.ts` (`toWireAnnotation`, `toWireSpeed`, `toWireWebcam`). `limits.drift.test.ts` also parses every `check_range` in `crates/frostcap-project/src/lib.rs` and the "Editor v2 fields" tables.
- **Annotations:** `lib/annotations.ts` (creation, fade, hit test, drag) and `lib/overlay.ts` (canvas drawing in screen-content space: after the zoom, under cursor/webcam/captions, at most 8 at once, strokes not scaled by zoom, spotlight clipped to the content, blur/pixelate sample the frame). Draw with a tool in the Annotate tab by dragging on the preview (`Preview.tsx`, mapped through `canvasToContent`/`contentToCanvas`), select and drag handles, double-click text to edit; the selected outline is focusable (arrows move, Alt+arrows resize, Enter edits text, Ctrl+D duplicates, Delete removes). The timeline "Notes" track has draggable/resizable bars (`RangeTracks.tsx`).
- **Speed:** `lib/speed.ts`. Speed regions are striped bars on their own track; `outputDuration`/`sourceToOutput` apply cuts first, then speed. Preview playback sets `playbackRate` (pitch follows speed).
- **Webcam:** margin, border, mirror, brightness/contrast/saturation, shadow, green screen (CbCr key in `lib/chroma.ts`, eyedropper samples the camera frame) and background replacement (disabled with a hint until the key is on). The preview approximates the export; the exporter is authoritative.
- **Images:** `pick_image` then `import_background` for the framed-screen background and the webcam background. Images are loaded through the asset protocol (Tauri only; the browser demo shows the file name).
- **Suggest cuts:** `suggest_cuts` with the documented defaults; proposals are dashed bars on the video track, accepted one at a time or all at once as one undoable trim (`lib/cuts.ts`). Nothing is applied automatically.
- **Export:** AV1 is offered only when `encoder_capabilities().formats` lists it (written as MP4). Batch export picks aspects x formats (at most 8 files), writes next to the default output folder and shows per-job progress (`jobIndex`) and results.
- **Screenshots:** `node ui/scripts/screenshots.mjs --scenes v2` writes annotations, webcam, background-image, suggest-cuts and batch-export PNGs.
